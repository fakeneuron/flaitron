Make the src/ui and SHARED_PURE tier gates reject bare Node builtin specifiers (`'fs'`, `'fs/promises'`) the same way they reject `node:*`.

- **Matcher pitfall.** The gate matches `group` patterns with the `ignore` package, gitignore-style. An unanchored `fs` matches any path component named `fs`, so it would also ban a sibling `./fs` and `lib/fs`. A leading `/` anchors it to the whole specifier, and a directory pattern still covers `fs/promises`. The fixtures pin both sides.
- Probes in `viz/src`: no live bare builtin import exists, and no `package.json` dependency shares a builtin's name, so the gate lands without a source change. A browser polyfill package named like a builtin (`buffer`, `process`) would now be banned in src/ui; that is intended while Node types stay global ([[FE-136]]).
- Assumption: the list follows the Node that runs lint, so a future Node builtin is covered once lint runs on it. The test loop over `builtinModules` guards the matcher mechanics, not coverage of unreleased builtins.
