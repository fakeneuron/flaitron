**Discovery Notes:**

- Read set: `viz/tsconfig.json`, `viz/tsconfig.browser.json`, `viz/tsconfig.node.json`, `viz/package.json` scripts, `viz/src/sharedPure.test.ts`, `viz/eslint.config.js`, `viz/README.md` §"Architecture — three tiers"; natabula `frontend/tsconfig{,.app,.node}.json`, `docs/QUALITY-STACK.md` (NAT-222 note), `docs/STACK-TENDENCIES.md`. No probe.
- natabula's reason for the layout was typescript-eslint `projectService`: the service opens the nearest `tsconfig.json` and follows `references` to find a file's owner. viz's ESLint is not type-aware (no `projectService` / `parserOptions.project`), so that reason does not carry over.
- Probes ran on a scratch copy of viz (`src`, `public`, configs; `node_modules` symlinked). Root became `files: []` + `references`; the old root `compilerOptions` moved to a `tsconfig.base.json` the tiers extend.
  - **Composite tiers fail.** `tsc -b --force` exited 1 with 5× TS6307: a composite project may not import a file outside its own file list. viz's tiers cross on purpose — Node modules import `sseChange`/`parser`/`tasknote`/`fence` (browser tier), and `tasknote.test.ts` (browser tier) imports `tasknote-parse` (Node tier). Composite would need cross-project declaration emit, which is a redesign.
  - **Non-composite tiers pass.** TypeScript 5.9 `tsc -b` builds non-composite referenced projects: exit 0 on the clean tree. A seeded `process` in `src/ui/` failed with TS2591 and a seeded `window` in `src/` failed with TS2304, so both tier guards survive. `tsc -b` writes `tsconfig.{browser,node}.tsbuildinfo` beside the configs; `*.tsbuildinfo` is already in root `.gitignore`.
  - **Editor coverage improves.** A tsserver probe (open + `projectInfo`) assigns `src/ui/App.tsx`, `src/parser.ts`, `src/tasknote.test.ts` → `tsconfig.browser.json` and `src/devApi.ts`, `vite.config.ts` → `tsconfig.node.json`, all with 0 semantic diagnostics. In the current layout every file opens under root `tsconfig.json`, which carries Node and DOM types together, so a tier violation is invisible in the editor and only `npm run typecheck` catches it.
- **Bookkeeping does not shrink.** With `files: []`, parsing root yields no files, so the "empty root remainder" test passes vacuously. Something still has to catch a new file in no tier (e.g. `src/lib/x.ts`, outside both include sets): under the new layout `tsc -b` skips it and the editor gives it an inferred project. The remainder test would change from "parse root include" to "walk `src/**` + `vite.config.ts`", about the same size. The other cost is a new `tsconfig.base.json` (root can no longer carry shared `compilerOptions`).
- Best practices: tiers own type-checking either way; the gain is that the editor uses the same tier boundaries `typecheck` does. No duplicated include lists either way.
- Archive area `fe` matches the README table. Load-bearing: [[FE-136]] (browser tier), [[FE-138]] (node tier), [[FE-139]] (last root-only files into a tier), [[FE-140]] (root made editor-only; remainder test pinned; noted a remainder config with no inputs fails TS18003). No ⚠️ pointer, no `supersedes:`.
