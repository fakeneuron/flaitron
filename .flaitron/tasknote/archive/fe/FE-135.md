**Discovery Notes:**

> Carried from the retired sidequest stub:
>
> **Idea**
>
> A `/// <reference types="node" />` directive in a src/ui or SHARED_PURE file pulls in Node's ambient types (`NodeJS.*`, `Buffer`, `process`) with no import node. So neither core `no-restricted-imports` nor `flaitron/no-restricted-import-expressions` sees it. The FE-134 review confirmed `/// <reference types="node" />\nexport type T = NodeJS.Process;` in src/ui gets no tier report. Check first whether tsconfig `types` already blocks it at typecheck; if not, gate the directive in the same three blocks.
>
> **Resume anchor**
>
> FE-134 Phase 3: review findings dispositioned, about to record the receipt and close.

- Read set: `viz/eslint.config.js`, `viz/tsconfig.json`, `viz/src/sharedPure.test.ts`, `viz/README.md` §"Hard rule", and the installed `@typescript-eslint/eslint-plugin` rule `triple-slash-reference`.
- **Drift: the stub's typecheck question turns the premise around.** `viz/tsconfig.json` is the only tsconfig and sets `"types": ["node"]` for all of `src/**`. A probe `src/ui/__probe.ts` holding `export type T = NodeJS.Process; export const b: Buffer | null = null;`, **with no directive**, passed `npm --prefix viz run typecheck` (exit 0) and lint (exit 0). The same file with the directive also lints clean. So the directive brings in nothing that is not already ambient. Gating it alone closes no gap today. The real gap is project-wide `types: ["node"]`. Probe file removed.
- `tseslint.configs.recommended` already turns on `@typescript-eslint/triple-slash-reference` with defaults `{ lib: 'always', path: 'never', types: 'prefer-import' }`. `prefer-import` reports a `types` directive only when the file also imports the same module, so `/// <reference types="node" />` by itself passes. Setting `types: 'never'` in the three tier blocks is a one-line gate. Its message is the rule's own ("use `import` style instead"); it cannot carry a README pointer.
- No live `process.` / `NodeJS` / `Buffer` use in non-test `src/ui`.
- Area `fe` matches `.flaitron/tasknote/README.md` §"Archive layout". Archive grep for `tsconfig` / `"types"` / `triple-slash`: [[FE-106.4]] notes `"types": ["node", "vitest/globals"]` (since then trimmed to `["node"]`). No note decided to scope Node types per tier. [[FE-134]] is the predecessor.
- Best practices: configure the stock `triple-slash-reference` rule. Do not add a new visitor to the local plugin, because a directive is a comment and not an import node. Put it in `tierImportRules` so the three blocks cannot drift apart. `path` stays at its `'never'` default and `lib` at `'always'`; a `lib` reference cannot pull in Node types.
- Clarification (AskUserQuestion): operator chose **Gate + file split**. Assumption: typescript-eslint deep-merges rule options with the defaults, so `{ types: 'never' }` keeps `path: 'never'`.
- Exit judgment: the premise drift was settled by the operator's scope answer before the exit, so the verdict is a plain Proceed → skip 🛠️.
