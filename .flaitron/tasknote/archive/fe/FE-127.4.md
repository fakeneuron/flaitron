# FE-127.4 | watch-late-dirs

[← PLAN.md](../PLAN.md) · ✅ Completed · 🔗 [[FE-EPIC-127]]

## 🎯 Goal

A project whose `tasknote/` or `tasknote/archive/` does not exist at dev-server start still fires SSE change events for notes created there later, because both watchers anchor on the project's `.flaitron/` root (which discovery guarantees exists) with `depth` and `ignored` re-anchored to it.

## ✅ Acceptance

- [x] Both watchers watch each project's `.flaitron/` root; the hot watcher polls at depth 1, the archive watcher watches natively at depth 3 — `npm --prefix viz test -- flaitronWatch watchSet`
- [x] Hot reach is exactly `PLAN.md` + `tasknote/*.md`; archive reach is exactly `tasknote/archive/<area>/*.md`; every other path under the root (`.flaitron/core/`, a stray `archive/README.md`, deeper nesting) is pruned by path shape — `npm --prefix viz test -- flaitronWatch`
- [x] Integration: with real chokidar, a project started with no `tasknote/` dir fires events for a later active note and a later `archive/<area>/<file>.md` (archive dir created after start), and never traverses `.flaitron/core/` — `npm --prefix viz test -- flaitronWatch`
- [x] Typecheck, lint, and the full viz suite stay green — `npm --prefix viz run typecheck && npm --prefix viz run lint && npm --prefix viz test`

## 🧩 Subtasks

- [x] `watchSet.ts`: replace `watchSets` (hot/archive path lists) with `watchRoots` (each project's `.flaitron/` dir); update its tests
- [x] `flaitronWatch.ts`: replace `ignoreNonMarkdown` / `ignoreOutsideArchiveArea` with root-anchored `ignoreOutsideHotReach` / `ignoreOutsideArchiveReach` (Set lookups, path-shape first so the stats-less pre-check prunes too); `WATCH_HOT_OPTIONS` → `hotWatchOptions(projects)` at depth 1, `archiveWatchOptions(projects)` at depth 3
- [x] `vite.config.ts`: watch `watchRoots(discovered)` with both option builders
- [x] Tests: predicate unit tests, option pins, and a real-chokidar late-dir integration test
- [x] Run targeted tests, typecheck, lint, full viz suite

**Implementation Notes:**

- `watchSet.ts`: `watchSets` → `watchRoots` (each `.flaitron/` dir, `dirname(planPath)`).
- `flaitronWatch.ts`: `ignoreOutsideHotReach` (root, PLAN.md, tasknote dir, `tasknote/*.md`) and `ignoreOutsideArchiveReach` (root, tasknote dir, archive dir, area dirs, `archive/<area>/*.md`), both Set-backed and shape-first; `hotWatchOptions(projects)` depth 1 polled, `archiveWatchOptions(projects)` depth 3 native.
- `vite.config.ts`: both watchers on `watchRoots(discovered)`.
- Tests: option pins re-pinned at 1 / 3; predicate tests cover stats-less pre-checks, `scratch.txt`, stray `archive/README.md`, nested area, `core/`, `PLAN-ARCHIVE.md`, per-project; one real-chokidar test starts both watchers on a project with no `tasknote/`, then creates `archive/core/CORE-001.md` (via `mkdir -p`), `archive/STRAY.md`, `tasknote/scratch.txt`, `core/viz/README.md`, `tasknote/CORE-002.md` — asserts exactly one archive and one hot event and that `core/` is never in `getWatched()`.
- Integration test wrinkle: macOS `fs.watch` dropped every event written right after chokidar's `ready` (the hot poller saw its file; the native watcher saw nothing). A 500 ms settle after `ready` fixes it, commented in the test; production is unaffected (the watcher starts long before any dir appears). Stable 5/5 consecutive targeted runs.
