# FE-127.2 | devapi-guarded-catch

## 🎯 Goal

A malformed `/api/*` request (e.g. `GET /api/plan//a:99999`) gets an HTTP status instead of an unhandled rejection that exits the Vite dev process.

## ✅ Acceptance

- [x] `projectFromQuery` returns `{ error }` (not a throw) for a URL `new URL` rejects, so every handler answers 400 — `npm --prefix viz test -- devApi`
- [x] `guarded` catches a handler rejection, logs it to stderr, and answers 500 when headers are unsent — `npm --prefix viz test -- devApi`
- [x] `guarded` destroys the response (no second write) when the handler fails after headers were sent — `npm --prefix viz test -- devApi`
- [x] A test sends the malformed request through a real handler and asserts a 400 status, with no rejection — `npm --prefix viz test -- devApi`
- [x] Typecheck, lint, and the full viz suite stay green — `npm --prefix viz run typecheck && npm --prefix viz run lint && npm --prefix viz test`
- [ ] Live repro no longer kills the dev server — N/A — not run: the Path Access hook blocked the curl (it read the URL path `/api/projects` as a filesystem path), so no dev server was started; the unit tests drive the same stripped URL (`//a:99999`) through the real handlers. Hand-run: `npm --prefix viz run dev`, then `curl --path-as-is http://localhost:5120/api/plan//a:99999` should return 400 and the server stay up
