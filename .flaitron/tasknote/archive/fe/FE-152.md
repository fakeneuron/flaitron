# FE-152 | api-host-guard

[← PLAN.md](../PLAN.md) · ✅ Completed · 🔗 [[FE-127.3]]

## 🎯 Goal

Give `/api/*` its own DNS-rebinding defence by rejecting requests whose `Host` header is not a loopback name inside `guarded`, instead of relying on Vite's `allowedHosts` middleware running ahead of plugin middleware.

## 📝 Phase 1: Discovery

- [x] Reviewed the task entry in PLAN.md

- [x] **Relevance Assessment**

  **Verdict:** Proceed
  **Rationale:** `guarded` (`viz/src/devApi.ts:83`) runs loopback → method → origin guards; none inspects `Host`. In a DNS-rebinding attack the browser connects to 127.0.0.1 (passes `loopbackGuard`) and treats `evil.example:5120` as same-origin (`Sec-Fetch-Site: same-origin`, no `Origin` on a same-origin GET, `Referer` absent under `no-referrer`), so `originGuard` passes too. The only defence today is Vite's `allowedHosts` host-check middleware, which `originGuard.ts`'s own comment names as the DNS-rebinding defence. Gap is real.

- [x] Read relevant source files — `viz/src/devApi.ts`, `viz/src/originGuard.ts`, `viz/vite.config.ts` (allowedHosts at :156, imports `DEV_PORT` from `originGuard.ts`), `viz/src/devApi.test.ts` (`makeReq` helper, `guarded` describe block), `SECURITY.md` §Visualizer.

- [x] **Best Practices Review** — new guard follows the existing `xGuard(req, res): boolean` shape and lives inside the single `guarded` prelude, so no handler can skip it. The host list moves to `originGuard.ts` beside `ALLOWED_ORIGINS` (already the module `vite.config.ts` imports `DEV_PORT` from) so the two allowlists cannot drift.

- [x] **Archive skim** — `archive/fe/` (area confirmed via README table: `FE-*` → `archive/fe/`). `FE-127.3` added `loopbackGuard` to `guarded` and its comment notes `allowedHosts` only filters Host; `FE-128` pinned `server.host` to `localhost` and logged that `allowedHosts`/CSP name `127.0.0.1` deliberately; `FE-119` added the `Sec-Fetch-Site` reject. Assumptions: (1) allowlist mirrors `allowedHosts` exactly (`localhost`, `127.0.0.1`), hostname-only, port ignored, case-insensitive — matching Vite's hostname semantics; (2) absent or malformed `Host` fails closed with 403 (Node already 400s a Host-less HTTP/1.1 request; HTTP/1.0 is the only path); (3) Host parsed with a strict regex rather than `new URL`, so userinfo tricks like `x@localhost` cannot normalize into an allowed name; (4) check runs after `loopbackGuard`, before `methodGuard`.
