# FE-146 | project-data-error-hygiene

[← PLAN.md](../PLAN.md) · 📌 Sidequest (filed 2026-10-27)

## Idea

Two pre-existing `useProjectData` gaps (viz/src/ui/useProjectData.ts) surfaced by FE-145's external review, out of its scope. (1) When one scope's response is `!ok`, `load()` throws before committing the other scopes' successfully fetched slices, so those stay stale with no error flagged — commit healthy slices independently of the failing one. (2) `reset()` never clears the load errors, and `load()`'s catch has no `activeProjectRef` guard (the success path has one), so a failed load for project A can write an error after a switch to B — clear errors in `reset()` and guard the catch.
